# Koder

Personal Kanban PWA. Static, no build step. `index.html` + `css/styles.css` + ES modules
under `js/`, data from `js/projects.json` (regenerated by `scripts/gen-projects.sh`):

- `app.js` entry; `render.js` repaint seam; `board.js` / `sidebar.js` / `modal.js` UI
- `store.js` pure board logic; `ref.js` ticket refs (`HOLIT-3F7C`), pure and shared with
  the server; `archive.js` lifts done cards into the server's append-only archive
- `state.js` persistence; `sync.js` server sync; `connect.js` the "connect a device" token
  overlay; `pr-status.js` + `pr-status-view.js` live PR/CI chips (`GET /pr-status`)
- `pwa.js` SW glue; sync config in `js/config.local.js` (gitignored, copy from
  `config.example.js`)

Service worker in `sw.js` — adding a JS module means adding it to `SHELL_ASSETS`. Don't
touch `CACHE_NAME`: it's stamped from a content hash by `node scripts/stamp-sw.mjs`, run on
`main` before deploy and never on a feature branch (see "Deploying" in README.md).

Server (`server/`, Deno Deploy + KV): `main.ts` is the sync API plus the signed GitHub webhook
(`POST /webhooks/github`) that moves a card to Review on PR open and Done on merge;
`github.ts` holds the repo allowlist and PR status; `workflow.ts` the webhook helpers.

Tests: `npm test` from the repo root runs the JSDoc type check (`tsc --checkJs`) and
`node --test` over `tests/` (store/ref logic, the koder-ticket CLI, PR status, SW stamping,
project generation). Keep `store.js` and `ref.js` free of DOM/localStorage so this stays
true. Server changes also run `deno task check` and `deno task test` from `server/`. JS uses
`// @ts-check` + JSDoc types.

Specs for bigger work live in `docs/specs/` (agent orchestration, storage expansion).

## Koder skills

The koder-ticket and koder-sprint skills are mastered here
(`.claude/skills/<name>/SKILL.md`; koder-ticket's CLI source of truth is
`scripts/koder-ticket.sh`) and synced to `~/.claude/skills/` and the sibling
repos so cloud/mobile sessions can use the board. After editing any of them, run
`scripts/sync-skill.sh` and commit the changed copies in each repo. Never edit a
synced copy in place.

## Working preferences

- **Verify UI by driving a real browser, not ad-hoc scripts.** Use the browser tools on hand
  (`claude-in-chrome`, a browser MCP) to click through the change. Don't write throwaway
  Puppeteer/Playwright/CDP scripts to check it. Koda still does the final check.
- Serve locally with `npx serve` when a local server is genuinely needed — not
  `python http.server`.
